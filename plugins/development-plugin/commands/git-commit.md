# Git Commit

このコマンドは、git-operationsスキルを使用して、ステージングされている変更を分析し、その内容に適したコミットメッセージを自動生成してコミットを実行します。

## 使用方法

```
/git-commit
```

引数は不要です。現在ステージングされている変更を自動的に検出し、コミットを実行します。

## 処理フロー

### ステップ1: git-operationsスキルの起動

まず、git-operationsスキルを起動します。

```
/git-operations
```

### ステップ2: 現在の状態確認

以下のGitコマンドを並列で実行し、現在の状態を把握します：

```bash
# ステージングされているファイルと変更を確認
git status

# ステージングされている変更の詳細を確認
git diff --staged

# 最近のコミットメッセージを確認（スタイルの参考）
git log --oneline -10
```

### ステップ3: ステージング状態の確認

- ステージングされている変更がない場合は、ユーザーに通知して終了
- ステージングされている変更がある場合は、次のステップに進む

### ステップ4: コミットメッセージの作成

ステージングされている変更の内容を分析し、以下の点を考慮してコミットメッセージを作成します：

1. **変更の性質を特定**:
   - 新機能の追加 (add, implement, create)
   - 既存機能の更新・改善 (update, improve, enhance)
   - バグ修正 (fix)
   - リファクタリング (refactor)
   - ドキュメント更新 (docs)
   - テスト追加・修正 (test)
   - その他

2. **コミットメッセージの方針**:
   - 「何を」ではなく「なぜ」を重視
   - 簡潔に1〜2文の日本語で要約
   - リポジトリの既存のコミットメッセージスタイルに従う
   - 変更の目的や意図を明確に

3. **禁止事項**:
   - 機密情報やクレデンシャルをコミットしない
   - `.env`, `credentials.json` などのファイルがステージングされている場合は警告

### ステップ5: コミットの実行

作成したコミットメッセージでコミットを実行します：

```bash
git commit -m "<生成したコミットメッセージ>"
```

### ステップ6: 結果の確認

コミット後、以下のコマンドで結果を確認します：

```bash
# コミットが成功したか確認
git status

# 最新のコミットを表示
git log -1
```

### ステップ7: pre-commitフックへの対応

もしコミットがpre-commitフックによって失敗した場合：

1. フックによって修正されたファイルを確認
2. 以下を確認してamendが安全か判断:
   - 作成者が自分か: `git log -1 --format='%an %ae'`
   - プッシュされていないか: `git status` で「Your branch is ahead」を確認
3. 両方がtrueの場合のみ、修正を追加してamend:
   ```bash
   git add <修正されたファイル>
   git commit --amend --no-edit
   ```
4. そうでない場合は、新しいコミットを作成

## ベストプラクティス

- **コミット前に確認**: `git status` と `git diff --staged` で変更内容を必ず確認
- **適切な粒度**: 1つのコミットには論理的にまとまった変更のみを含める
- **機密情報の除外**: 認証情報やAPIキーなどを含めない
- **リポジトリスタイルの尊重**: 既存のコミットメッセージのスタイルに従う

## 注意事項

- このコマンドはステージングされている変更のみをコミットします
- ステージングされていない変更は含まれません
- コミット前に必ず変更内容を確認します
- git-operationsスキルのGit安全性プロトコルに従います
