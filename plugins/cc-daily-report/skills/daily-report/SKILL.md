# Claude Code 日報・振り返りスキル

## 概要

`cc-summarizer` Go スクリプトで `~/.claude/projects/` 以下のセッションファイルを並列解析し、
Claude Code作業データと今日のメモを素材にインタラクティブな振り返りを行う。
回答内容を `~/zettelkasten/Daily/YYYY-MM-DD.md` の `# ふりかえり` セクションに書き込む。

## 実行手順

### ステップ1：バイナリの準備

スクリプトのパスを特定する：

```
${CLAUDE_PLUGIN_ROOT}/scripts/cc-summarizer/main.go
```

バイナリが存在するか確認し、なければコンパイルする。OSに応じてバイナリ名を切り替える：

- Linux/macOS: `cc-summarizer`
- Windows: `cc-summarizer.exe`

バイナリが存在しない場合、以下のコマンドでコンパイルする：

```bash
cd "${CLAUDE_PLUGIN_ROOT}/scripts/cc-summarizer" && go build -o cc-summarizer ./main.go
```

Windowsの場合：
```powershell
cd "${CLAUDE_PLUGIN_ROOT}\scripts\cc-summarizer"; go build -o cc-summarizer.exe .\main.go
```

### ステップ2：スクリプト実行

引数なしで実行すると「今日（UTC日付）」のセッションを対象とする。
特定日付を指定する場合は `YYYY-MM-DD` 形式で引数を渡す：

```bash
"${CLAUDE_PLUGIN_ROOT}/scripts/cc-summarizer/cc-summarizer"
# または日付指定
"${CLAUDE_PLUGIN_ROOT}/scripts/cc-summarizer/cc-summarizer" 2026-03-29
```

出力はJSONで以下の構造を持つ（`references/report-format.md` 参照）。

### ステップ3：振り返り設定の読み込み

以下の2ファイルを読む：

1. **振り返り軸ファイル**: `~/zettelkasten/.claude/rules/daily-report.md`
   - 今月の振り返りテーマと問いが書かれている
   - ファイルが存在しない場合は「振り返り軸が設定されていません。`~/zettelkasten/.claude/rules/daily-report.md` を作成してください」と案内して終了

2. **今日のデイリーノート**: `~/zettelkasten/Daily/YYYY-MM-DD.md`（今日の日付）
   - 存在しない場合は空として扱う（エラーにしない）
   - `# メモ` セクションの内容を振り返りの素材として使う

### ステップ4：インタラクティブ振り返りQ&A

以下の手順でユーザーと対話する。

#### 4-1. 作業事実の提示

CC作業データから今日のプロジェクトと作業内容を **事実として** 箇条書きで提示する。
今日のメモがあればそれも合わせて表示する。

**禁止事項**: 「〜を達成しました」「〜ができました」などの評価・要約を加えない。
何をしたかという事実だけを並べる。

#### 4-2. 振り返り問いを1問ずつ聞く

振り返り軸ファイルの「今月の問い」を**テンプレートとして参照**し、CC作業データから読み取った具体的な対象（プロジェクト名・機能名・概念・問題）を当てはめて問いを生成する。問いは **1問ずつ** 提示する。

**質問の生成原則**:
- 振り返り軸の問いは「型」として使い、作業内容の具体的な固有名詞を入れて問いを立てる
  - NG: 「今日の作業を説明するとしたら？」
  - OK: 「cc-summarizerのリポジトリ集計ロジックの本質は何ですか？」
  - OK: 「Zettelkasten連携について、データフローの観点から説明してください」
- 問いの主語・目的語は必ず作業内容から取る（抽象的な「今日の作業」は使わない）
- 答えの方向を誘導しない
- ユーザーがまだ言語化できていないことを引き出すことを目的とする

**フォローアップ**: ユーザーの回答が表面的・曖昧な場合は、同様に具体的な固有名詞を使って掘り下げる：
- 「〇〇の中で、特に△△の部分はどう説明する？」
- 「そのとき〇〇が引っかかっていたのはなぜ？」
- 「〇〇を知らない人に説明するとしたら、何が一番難しい？」

ただし、フォローアップは1問につき1回まで。深追いしすぎない。

#### 4-3. 全問終了の確認

全問の回答が揃ったら「書き込んでもいいですか？」とは聞かずに、そのままステップ5に進む。

### ステップ5：Daily/への書き込み

`~/zettelkasten/Daily/YYYY-MM-DD.md` の `# ふりかえり` セクションを以下の内容で **置き換える**。

**置き換えの仕様**:
- `# ふりかえり` という見出し行以降をすべて新しい内容に置き換える
- `# メモ` セクションは一切変更しない
- ファイルが存在しない場合は新規作成する

**書き込む内容のフォーマット（`references/report-format.md` 参照）**:

```markdown
# ふりかえり

## Claude Code作業ログ
- **[プロジェクト名]**: [作業した内容（事実の列挙）]
- ...（セッションが0件の場合は「本日Claude Codeの利用なし」）

## [振り返り軸ファイルのタイトル（例：説明可能性）]

**Q: [問い1]**
[ユーザーの回答をそのまま記録。要約しない。フォローアップがあった場合はそのやり取りも含める]

**Q: [問い2]**
[ユーザーの回答]

...
```

書き込み完了後、ファイルパスをユーザーに伝える。

## エラーハンドリング

- `go` がインストールされていない場合：「Goのインストールが必要です（https://go.dev/dl/）」と案内する
- セッションが0件の場合：振り返りは続行する（Claude Code未使用の日もある）
- コンパイルエラーの場合：エラーメッセージをそのまま表示して対処法を提案する
- 振り返り軸ファイルがない場合：作成方法を案内して終了する

## 注意事項

- セッションファイルはUTCタイムスタンプで記録されているため、日本時間と最大9時間ずれる場合がある
- 機密情報（APIキー、パスワードなど）と思われる内容は日報に含めない
- `Warmup` メッセージのセッションは自動でスキップされる
- ユーザーの回答は要約せず、語尾や言い回しも含めてそのまま記録する
