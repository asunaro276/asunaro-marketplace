# Git Create PR

このコマンドは、git-operations-expertサブエージェントを使用して、現在のブランチの変更内容を分析し、プロジェクトのPRテンプレートに従った形式（存在する場合）または一般的な形式でドラフトプルリクエストを作成します。

## 使用方法

```
/git-create-pr
```

引数は不要です。現在のブランチとその変更内容を自動的に検出し、PRを作成します。

## 処理フロー

### ステップ1: git-operations-expertサブエージェントの起動

まず、Taskツールを使用してgit-operations-expertサブエージェントを起動します。

このサブエージェントは、GitとGitHubの操作に精通したエキスパートエージェントで、以下の処理を自律的に実行します。

### ステップ2: 現在の状態確認

以下のGitコマンドを並列で実行し、現在の状態を把握します：

```bash
# 現在のブランチとステータスを確認
git status

# ステージング済みの変更を確認
git diff --staged

# 未ステージングの変更を確認
git diff

# リモートブランチとの同期状態を確認
git status -sb

# 現在のブランチからの全コミット履歴を確認（ベースブランチから分岐後）
git log main...HEAD --oneline

# ベースブランチとの差分を確認
git diff main...HEAD
```

### ステップ3: 前提条件の確認と誘導

以下の順序で状態を確認し、適切なアクションをユーザーに促します：

#### 3-1: ブランチの確認

現在のブランチがmain/masterの場合：
- ユーザーに通知して `/git-branch` または `/git-branch-and-work` の実行を促す
- 処理を終了

#### 3-2: コミットの確認

ベースブランチ（main/master）からのコミットがない場合：

**3-2-1: 変更がある場合（ステージング済みまたは未ステージング）**:
- 変更内容を簡潔に表示
- `/git-commit` の実行を促す
- 処理を終了

**3-2-2: 変更もない場合**:
- まだ作業を開始していないことを通知
- `/git-branch` または `/git-branch-and-work` の実行を促す
- 処理を終了

#### 3-3: リモートブランチの確認

現在のブランチがリモートにプッシュされていない、または最新でない場合：
- リモートにプッシュ（ステップ7で実施）

### ステップ4: PRテンプレートの確認

プロジェクト内にPRテンプレートが存在するか確認します：

```bash
# PRテンプレートを検索
find . -type f \( \
  -name "pull_request_template.md" -o \
  -name "PULL_REQUEST_TEMPLATE.md" -o \
  -path "*/.github/PULL_REQUEST_TEMPLATE*" \
\) 2>/dev/null
```

**テンプレートが見つかった場合**:
- テンプレートファイルを読み込む
- テンプレートの構造と項目を把握

**テンプレートが見つからない場合**:
- ルートに.gitがない場合には親ディレクトリにテンプレートがある可能性があるので探索する
  -  見つかったら上記のテンプレートが見つかった場合の処理を行う
- それでも見つからない場合は一般的なPR形式を使用（後述）

### ステップ5: PRタイトルと本文の作成

すべてのコミット履歴と変更内容を分析し、PR内容を作成します。

#### PRタイトルの作成

- すべてのコミット内容を総括した簡潔なタイトルを作成
- 1行で完結する日本語のタイトル
- 変更の主要な目的を明確に示す

#### PR本文の作成

**PRテンプレートがある場合**:
- テンプレートの各セクションに対して適切な内容を記入
- テンプレートの構造とフォーマットを維持
- チェックボックスがある場合は適切に設定
- すべてのコミットと変更差分を分析して内容を作成

**PRテンプレートがない場合（一般的な形式）**:

```markdown
## Summary
<変更内容を1〜3つの箇条書きで要約>

## Changes
<主要な変更点を箇条書きで記載>

## Test plan
- [ ] テスト項目1
- [ ] テスト項目2
- [ ] テスト項目3

🤖 Generated with [Claude Code](https://claude.com/claude-code)
```

**Summary セクション**:
- すべてのコミットと変更差分を分析
- 主要な変更点を1〜3つの簡潔な箇条書きで要約
- 変更の「なぜ」と「何を」を明確に

**Changes セクション**:
- 具体的な変更内容を列挙
- ファイル単位または機能単位で整理

**Test plan セクション**:
- 変更内容に基づいた具体的なテスト項目を作成
- 機能追加の場合: 新機能の動作確認項目
- バグ修正の場合: 修正内容の確認と再現しないことの確認
- リファクタリングの場合: 既存機能が正常に動作することの確認
- マークダウンチェックリスト形式で記載

### ステップ6: ベースブランチの決定

デフォルトブランチを確認します：

```bash
# デフォルトブランチを確認
gh repo view --json defaultBranchRef --jq .defaultBranchRef.name 2>/dev/null || echo "main"
```

ベースブランチが main でない場合は、検出されたデフォルトブランチを使用します。

### ステップ7: ブランチのプッシュ（必要な場合）

リモートブランチが存在しない、または最新でない場合：

```bash
# リモートにプッシュ
git push -u origin <ブランチ名>
```

ネットワークエラー時は、git-operations-expertサブエージェントのリトライロジックに従います：
- 最大4回リトライ
- 指数バックオフ: 2s, 4s, 8s, 16s

### ステップ8: PRの作成

`gh` コマンドを使用してドラフトPRを作成します：

```bash
gh pr create --draft --title "<PRタイトル>" --body "$(cat <<'EOF'
<PR本文の内容>
EOF
)"
```

ベースブランチがmain以外の場合は `--base` オプションを追加：

```bash
gh pr create --draft --base <ベースブランチ> --title "<PRタイトル>" --body "$(cat <<'EOF'
<PR本文の内容>
EOF
)"
```

**重要**:
- `--draft` オプションを使用してドラフトPRとして作成します
- HEREDOCを使用して本文を渡すことで、改行やフォーマットを正しく保持します

### ステップ9: 結果の確認と表示

PR作成後：

1. 作成されたPRのURLを取得
2. PRのURLをユーザーに返す

## エラーハンドリング

### 1. PRが既に存在する場合

既存のPRを検出し、ユーザーに通知：

```bash
# 現在のブランチのPRを確認
gh pr list --head <ブランチ名>
```

既存PRがある場合は、そのURLを表示して終了。

### 2. 認証エラー

GitHub CLIの認証状態を確認：

```bash
# 認証状態を確認
gh auth status
```

認証されていない場合は、ユーザーに認証を促します：

```
gh auth login
```

### 3. ネットワークエラー

git-operations-expertサブエージェントのネットワークエラーハンドリングに従い、指数バックオフでリトライします。

### 4. リモートリポジトリが設定されていない

リモートリポジトリの設定を確認：

```bash
git remote -v
```

設定されていない場合は、ユーザーに設定を促します。

## 使用例

### 例1: 機能追加ブランチからPR作成（テンプレートあり）

```bash
# feature/add-user-authentication ブランチで作業・コミット後
/git-create-pr
```

→ PRテンプレートを検出し、それに従った形式でドラフトPRを作成

### 例2: バグ修正ブランチからPR作成（テンプレートなし）

```bash
# fix/login-error ブランチで作業・コミット後
/git-create-pr
```

→ 一般的な形式でドラフトPRを作成

### 例3: まだコミットしていない場合

```bash
# 変更はあるがコミットしていない状態で
/git-create-pr
```

→ `/git-commit` の実行を促すメッセージを表示

### 例4: mainブランチで実行した場合

```bash
# mainブランチで
/git-create-pr
```

→ `/git-branch` または `/git-branch-and-work` の実行を促すメッセージを表示

## ワークフロー連携

このコマンドは他のgit関連スラッシュコマンドと連携して使用します：

1. **ブランチ作成**: `/git-branch` または `/git-branch-and-work`
2. **作業とコミット**: `/git-commit`
3. **PR作成**: `/git-create-pr` ← このコマンド

## ベストプラクティス

- **明確なコミット履歴**: PRに含まれるコミットは明確で論理的な単位にする
- **適切なブランチ名**: ブランチ名は変更内容を反映したものにする
- **テンプレートの尊重**: PRテンプレートがある場合は、その項目をすべて適切に記入
- **テスト実施**: Test planに記載された項目を実際に実施

## 注意事項

- このコマンドはmain/masterブランチからは実行できません
- コミットがない場合は `/git-commit` を先に実行する必要があります
- 変更もコミットもない場合は `/git-branch` を先に実行する必要があります
- リモートにプッシュされていない変更は自動的にプッシュされます
- git-operations-expertサブエージェントのGit安全性プロトコルに従います
- すべてのコミット（最新だけでなく全コミット）を分析してPR内容を作成します
- PRテンプレートの検索は `.github` ディレクトリとルートディレクトリで行います
- PRはドラフト状態で作成されます（レビュー準備ができたら手動でReady for reviewに変更してください）
