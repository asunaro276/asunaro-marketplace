# Git Branch and Work

このコマンドは、git-operations-expertサブエージェントを使用して、現在の変更内容または命令内容に基づいた適切なブランチ名を生成し、新しいブランチを作成してから、指定された作業を実行します。

## 使用方法

```
/git-branch [作業内容]
```

- **作業内容** (オプション): ブランチ作成後に実行したい作業の説明
  - 指定した場合: その内容に基づいてブランチを作成し、作業を実行
  - 指定しない場合: 現在の変更内容に基づいてブランチを作成、または変更がなければユーザーにヒアリング

## 処理フロー

### ステップ1: git-operations-expertサブエージェントの起動

まず、Taskツールを使用してgit-operations-expertサブエージェントを起動します。

このサブエージェントは、GitとGitHubの操作に精通したエキスパートエージェントで、以下の処理を自律的に実行します。

#### サブエージェントへのプロンプト例

**重要**: サブエージェントの責務は**ブランチの命名とブランチ作成のみ**です。タスクの実行は親エージェントが行います。

##### 例1: 作業内容が指定されている場合

```
以下の作業内容に基づいて適切なブランチ名を生成し、origin/mainから新しいブランチを作成してください。

作業内容: {ユーザーが指定した作業内容}

手順:
1. 作業内容を分析し、適切なtype(feature/fix/refactor/docs/testなど)を決定
2. ブランチ名を生成（形式: <type>/<brief-description>）
3. git fetch origin main を実行
4. git switch -c <ブランチ名> origin/main でブランチを作成
5. git branch --show-current で作成を確認

注意: ブランチ作成が完了したら、作業はここで終了です。タスクの実装は行わないでください。
```

##### 例2: 変更内容がある場合

```
現在の変更内容を分析し、適切なブランチ名を生成してorigin/mainから新しいブランチを作成してください。

手順:
1. git status, git diff, git diff --staged を並列実行して変更内容を確認
2. 変更内容からtype(feature/fix/refactor/docs/testなど)を判断
3. ブランチ名を生成（形式: <type>/<brief-description>）
4. git fetch origin main を実行
5. git switch -c <ブランチ名> origin/main でブランチを作成
6. git branch --show-current で作成を確認

注意: ブランチ作成が完了したら、作業はここで終了です。変更内容のステージングや追加作業は行わないでください。
```

##### 例3: 変更内容がなく、ヒアリングが必要な場合

```
ユーザーに作業内容をヒアリングし、それに基づいて適切なブランチ名を生成してorigin/mainから新しいブランチを作成してください。

手順:
1. git status で変更がないことを確認
2. AskUserQuestionツールでユーザーに作業内容をヒアリング
3. ヒアリング内容からtype(feature/fix/refactor/docs/testなど)を判断
4. ブランチ名を生成（形式: <type>/<brief-description>）
5. git fetch origin main を実行
6. git switch -c <ブランチ名> origin/main でブランチを作成
7. git branch --show-current で作成を確認

注意: ブランチ作成が完了したら、作業はここで終了です。タスクの実装は行わないでください。
```

### ステップ2: 現在の状態確認（サブエージェントが実行）

以下のGitコマンドを並列で実行し、現在の状態を把握します：

```bash
# 現在のブランチとステータスを確認
git status

# 変更内容の確認（ステージング済み）
git diff --staged

# 変更内容の確認（未ステージング）
git diff

# 現在のブランチ名を確認
git branch --show-current
```

### ステップ3: origin/mainの最新化（サブエージェントが実行）

現在のブランチを変更せず、リモートのmainブランチの最新状態を取得します：

```bash
# リモートのmainブランチを最新化
git fetch origin main
```

これにより、現在の作業ブランチを維持したまま、最新のorigin/mainの状態を取得できます。新しいブランチはこのorigin/mainから作成されます。

### ステップ4: ブランチ名の決定（サブエージェントが実行）

#### 4-1: コマンド引数がある場合

コマンド実行時に作業内容が指定されている場合：
1. その作業内容を分析
2. 内容に適したブランチ名を生成

#### 4-2: 変更内容がある場合

現在ステージング済みまたは未ステージングの変更がある場合：
1. 変更内容を分析（どのファイルが変更されているか、どのような変更か）
2. 変更の性質を特定：
   - feature: 新機能の追加
   - fix: バグ修正
   - refactor: リファクタリング
   - docs: ドキュメント更新
   - test: テスト追加・修正
   - その他
3. 変更内容を簡潔に表すブランチ名を生成

#### 4-3: 変更内容がない場合

変更がなく、コマンド引数も指定されていない場合：
1. ユーザーに作業内容をヒアリング
2. ヒアリング内容に基づいてブランチ名を生成

#### ブランチ名の命名規則

ブランチ名は以下の形式で生成します：

```
<type>/<brief-description>-$(date '+%Y%m%d%H%M%S')
```

- **type**: feature, fix, refactor, docs, test など
  - fix, hotfixは明示的に指定されたときのみ使う
- **brief-description**: 作業内容を簡潔に表す英語の説明（kebab-case）

例：
- `feature/add-user-authentication`
- `fix/resolve-login-error`
- `refactor/improve-api-structure`
- `docs/update-readme`

### ステップ5: ブランチの作成（サブエージェントが実行）

生成したブランチ名で、origin/mainから新しいブランチを作成します：

```bash
# origin/mainから新しいブランチを作成して切り替え
git switch -c <ブランチ名> origin/main
```

ブランチ作成後、以下で確認：

```bash
# 現在のブランチを確認
git branch --show-current
```

---

**ここまでがサブエージェントの責務範囲です。**

サブエージェントはブランチ作成を確認したら、作業を完了して制御を親エージェントに戻します。
以降のステップは親エージェント（メインエージェント）が実行します。

---

### ステップ6: 作業の遂行（親エージェントが実行）

サブエージェントからブランチ作成の報告を受けた後、親エージェントが以下の作業を実行します：

#### 6-1: コマンド引数がある場合

指定された作業内容を実行します。作業内容に応じて：
- コードの実装
- ファイルの作成・編集
- テストの追加
- ドキュメントの更新
- など

#### 6-2: 変更内容が既にある場合

1. 既存の変更内容を確認
2. 必要に応じて追加の作業を実施
3. 変更をステージング：
   ```bash
   git add <変更されたファイル>
   ```

#### 6-3: ヒアリングした場合

ヒアリング内容に基づいて作業を実行します。

### ステップ7: 作業完了の確認（親エージェントが実行）

作業完了後、状態を確認：

```bash
# 現在の状態を確認
git status

# 変更内容の確認
git diff
git diff --staged
```

## 使用例

### 例1: 作業内容を指定してブランチ作成

```
/git-branch ユーザー認証機能を追加
```

→ `feature/add-user-authentication` ブランチを作成し、ユーザー認証機能の実装を開始

### 例2: 既存の変更内容からブランチ作成

ログイン画面のバグ修正コードを既に編集済みの状態で：

```
/git-branch
```

→ 変更内容を分析し、`fix/login-screen-bug` などのブランチを作成

### 例3: 変更なしでヒアリングからブランチ作成

変更がない状態で：

```
/git-branch
```

→ ユーザーに作業内容をヒアリングし、その内容に基づいてブランチを作成。その後命令に従って作業を行う

## ベストプラクティス

- **明確な作業内容**: ブランチ名が明確になるよう、作業内容は具体的に指定
- **適切なタイミング**: 新しい作業を始める前にブランチを作成
- **mainブランチの保護**: mainブランチで直接作業せず、必ず機能ブランチを作成
- **ブランチの粒度**: 1つのブランチには論理的にまとまった機能や修正のみを含める

## 注意事項

- 現在のブランチに未コミットの変更がある場合、それらの変更は新しいブランチに引き継がれます
- ブランチ作成前に重要な変更はコミットしておくことを推奨します
- git-operations-expertサブエージェントのGit安全性プロトコルに従います
- 既に同名のブランチが存在する場合は、異なる名前を提案します
