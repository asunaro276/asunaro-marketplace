# 問いの種類

## テーブル

| 作業の性質 | ①目的を問う | ②妥当性を問う |
|---|---|---|
| 実装・ロジック系 | 「〇〇を実装しようとしたとき、解こうとしていた問題は何でしたか？」 | 「その問題に対して、〇〇という実装はどう応えていますか？」 |
| 設計・アーキテクチャ系 | 「〇〇という構造にしようとしたとき、何を優先しようとしていましたか？」 | 「その優先事項に対して、〇〇という設計はどう機能しましたか？」 |
| 判断・選択系 | 「〇〇と△△を比較していたとき、何を判断軸にしようとしていましたか？」 | 「その判断軸で見たとき、〇〇を選んだことはどう評価できますか？」 |
| トレードオフ明示系 | 「〇〇を得る一方で△△というコストが生じていますが、このトレードオフをどう捉えて意思決定しましたか？」 | 「〇〇と△△のどちらを手放すことが難しかったですか？その理由は何ですか？」 |
| 反復改善系 | 「〇〇を繰り返し修正していたとき、最終的に何を満たそうとしていましたか？」 | 「その基準に対して、今の状態はどこまで達していると思いますか？」 |
| トラブル・デバッグ系 | 「〇〇に詰まっていたとき、何がわからなかったのですか？」 | 「解決したあと、何が見えるようになりましたか？」 |

## トレードオフの検出

会話履歴から以下が読み取れる場合は「トレードオフ明示系」を優先する：

- サイズ・速度・複雑度が増加した（出力が77KBになった、ビルドが毎回走る、等）
- 何かを追加した結果、別の何かを失った・犠牲にした
- 複数の選択肢を明示的に比較していた

## NG

- 「どう機能するか」という問いはメリットしか引き出さないため、トレードオフ系には使わない
- 「〇〇を人に説明するとしたら」という他者説明フレームは使わない
- yes/noで答えられる問いはNG（常にオープンクエスチョン）
